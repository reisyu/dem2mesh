# GML地形データ処理スクリプト (Grasshopper/Rhino)

国土地理院のGML形式地形データを読み込み、平面直角座標系（JGD2011 / JGD2024）に変換してRhinocerosの3Dメッシュを生成するGrasshopperスクリプトです。

## 概要

このスクリプトは、日本の測量計算規則に準拠した高精度な座標変換を実装しており、国土地理院が提供する標高データ（DEM）を建築・土木・GIS分野で活用できる形式に変換します。

### 主な機能

- **GML形式データの読み込み**: 国土地理院の標準形式に対応
- **高精度座標変換**: 平面直角座標系（JGD2011 / JGD2024）への変換。国土地理院の計算方法（6次展開）で、国土地理院の測量計算サイトと 0.05 mm 以内で一致（平面位置は JGD2011 と JGD2024 で同じ。標高の扱いは「注意: 測地成果2011と測地成果2024」を参照）
- **Rhino の単位への換算**: 座標と標高を Rhino の文書の単位（mm・m など）に換算して出力
- **自動ゾーン検出**: 範囲の中心の経度から平面直角座標系の系を推定（経度だけで判定するため、北海道などでは誤ることがある）
- **範囲クリッピング**: 指定領域の抽出が可能
- **サンプリング制御**: データ量の調整が可能
- **複数区画の統合**: 隣り合う複数のGMLを1つの格子にまとめ、境目のない1枚のメッシュを生成

## パラメータ

### 入力パラメータ

| パラメータ名 | 型 | 説明 |
|------------|-----|------|
| `xml_data` | List<string> | GML形式のXMLデータ（必須）。1区画につき1要素。入力は **List Access** に設定する |
| `jgd_zone` | int | 平面直角座標系のゾーン番号（1-19）。0以下で自動検出 |
| `sample_step` | int | サンプリングステップ（1以上）。大きいほど粗くなる |
| `target_point` | Point3d | クリッピング中心点（Rhino の文書の単位。Unsetでクリッピングなし） |
| `size` | double | クリッピング範囲の一辺（Rhino の文書の単位。0 以下でクリッピングなし） |
| `type_output` | int | 種別による分け方（0: 分けない, 1: 種別ごとに別のメッシュ, 2: 種別ごとに作って1枚に結合）。未接続なら 0 |

以前あった `mode`（処理モード）は Version 1.2 で廃止しました（下の「処理モードの廃止」を参照）。

### 出力パラメータ

| パラメータ名 | 型 | 説明 |
|------------|-----|------|
| `info` | List<string> | 処理情報（範囲、ゾーン、設定、種別ごとの面の数、区画ごとのメッシュ番号と srsName など） |
| `output_mesh` | Mesh | 生成された3Dメッシュ（座標・標高は Rhino の文書の単位）。`type_output` = 1 のときは空 |
| `type_meshes` | List<Mesh> | 種別ごとのメッシュ（頂点カラー付き）。`type_output` = 0 のときは空 |
| `type_names` | List<string> | `type_meshes` と同じ順の種別名 |

`type_output`・`type_meshes`・`type_names` は、Grasshopper のスクリプトコンポーネントに入力・出力として追加してください。

### サンプル定義 `dem2mesh.gh`

下の設定をすべて済ませた Grasshopper 定義です（Rhino 8.35 で作成）。開くと、①GMLを指定 → ②読み込み → ③設定 → ④メッシュを作る → ⑤結果、の順に色分けしたグループと説明メモが並んでいます。

- **① ファイルの選択:** File Path コンポーネントで選びます。右クリック →「Select many existing files」で複数、「Select one existing file」で1つを選べます。
  - **最初はファイルを選んでいない状態**（パスは空）で保存してあります。そのため、開いた直後は Read File にオレンジの警告が出て、info は「Wait: xml_data が未入力です。」になります。
  - **GMLデータはリポジトリに含めていません。** 下の「データの入手」のとおり、使いたい地域のデータをダウンロードしてから選んでください。
- **③ 設定の選択:** 設定はすべて Value List（▼で選ぶ一覧）です。
  - 平面直角座標系は「系番号と対象の都道府県」で選べます（内容は下の系の一覧と同じ）。最初は「自動判定」になっています。自動判定は経度だけで推定し、北海道などでは誤るので、対象地域の系が分かっていれば選んでください。
  - 間引きは 1・2・3・4・5・10 から、種別による分け方は意味付きの一覧から選びます。
- **コードの更新:** ④のコンポーネントには、`dem2mesh.cs` と同じコードが埋め込まれています。`dem2mesh.cs` を更新しても、.gh の中のコードは自動では変わりません。入出力はそのままで、コードだけ貼り直してください。
- **字下げの違い:** 開いたときに `RunScript` の引数の字下げがタブに変わりますが、中身は同じです。

### データの入手

読み込むGMLは、国土地理院の基盤地図情報です。再配布に手続きが必要なため（下の「使用データについて」を参照）、リポジトリには入れていません。使う人がそれぞれ入手してください。

1. [基盤地図情報ダウンロードサービス](https://service.gsi.go.jp/kiban/) で「数値標高モデル」を開きます。
2. 使いたい地域のメッシュを選び、DEM（5mメッシュ・10mメッシュなど）をダウンロードします。
3. 展開したGML（`FG-GML-…-DEM5A-….xml` など）を、`dem2mesh.gh` の File Path で選びます。隣り合う区画をまとめて選ぶと、1枚のメッシュになります。

- **置き場所:** どこでも構いません。このフォルダの `sample/` に置くと、`.gitignore` で除外されているので、誤ってコミットすることがありません。
- **解像度:** 5mと10mなど、セルの大きさが違うデータは同時に選べません。

### Grasshopper での設定（Rhino 8 の C# Script コンポーネント）

Rhino 8.35 の C# Script コンポーネントで確かめた手順です。

1. **入出力を先に作る。** 入力と出力を上の表の名前で作り、入力の型（Type Hint）とアクセスを次のとおり設定します。

   | 入力 | 型 | アクセス |
   |---|---|---|
   | xml_data | string | **List Access** |
   | jgd_zone | int | Item |
   | sample_step | int | Item |
   | target_point | Point3d | Item |
   | size | double | Item |
   | type_output | int | Item |

   出力 `out` は残したままで構いません。

2. **コードを貼る。** そのあとで `dem2mesh.cs` の内容をコンポーネントに貼ります。
   - 上の設定どおりなら、コンポーネントが作る `RunScript` の引数がファイルの引数とまったく同じになります。
   - プログラムから（API の `SetSource` で）コードを入れて試したところ、`RunScript` の引数は、いまコンポーネントにある入出力に合わせて書き換えられました。入出力を作る前に貼ると、引数が既定の `x, y` などに置き換わります。スクリプトエディタの画面から貼った場合の動きは、まだ試していません。

3. **GMLを読み込む。** GMLのパスを書いた Panel → **Read File**（右クリックで **Per Line をオフ**にして、ファイル全体を1つの文字列で出す）→ `xml_data` とつなぎ、`xml_data` を **Flatten** します。
   - Read File はファイルごとに別の枝で出力します。Flatten しないと、区画ごとに別々に実行され、つながらない別々のメッシュになります（4区画で4回実行され、225×150点のメッシュが4つできることを確かめました）。

4. **プレビューの見え方。** 頂点カラーは、Grasshopper のプレビューにも表示されます。ただ、面の線が赤で描かれるので、縮小すると全体が赤く見えます。拡大するか、Bake すると色がはっきり見えます。Bake したメッシュにも頂点カラーは残ります。

### 以前の定義からの移行（Version 1.1 以前）

- **`mode` の入力:** `mode` の入力がある古い定義にこのコードを貼っても、`mode` は使われないだけで動きます。Version 1.1 の `dem2mesh.gh` で確かめました（Rhino 8.35、プログラムから貼った場合）。不要なら入力を消してください。
- **座標の大きさ:** 以前は座標をメートルのまま出していたので、ミリメートルの文書では1000分の1の大きさになっていました。いまは文書の単位に換算するので、Bake 済みのものと重ねるときは大きさが変わることに注意してください。

## 座標変換と単位

### 処理モードの廃止（Version 1.2）

以前は `mode` で、座標変換の次数（3次・6次）と標高の取り方（そのまま・補間）を選べました。確かめた結果、どちらにも意味がなかったので廃止しました。

| 以前のモード | 確かめた結果 |
|---|---|
| 0: 高速（3次展開） | 6次との差は最大 0.016 mm（系の中央から 230 km 離れた点でも）。速さの差は、点ごとに定数を計算し直していたためで、次数のせいではなかった |
| 1: 標準（6次展開） | 国土地理院の測量計算サイトと 0.05 mm 以内で一致。これを常に使う |
| 2: 高精度（6次展開＋補間） | メッシュの頂点は DEM の格子点（セルの中心）そのものなので、補間しても値は変わらない（Rhino 8 で全頂点の差が0）。実装の誤りを直しても効果は出ない |

- **いまの座標変換:** 常に6次展開で計算します。楕円体と原点で決まる定数は、最初に1回だけ計算します。
- **補間が意味を持つ場合:** データ点とは別の位置に点を作り直すときです（平面直角座標の X・Y 軸にそろった格子にする、間引くときに平均をとる、など）。必要になったら、別の機能として作ります。

### Rhino の単位

- **出力:** 座標はメートルで計算し、出力する座標と標高を Rhino の文書の単位に換算します（mm の文書なら 1 m = 1000）。info の `Units:` に、換算に使った単位が出ます。
- **入力:** `target_point` と `size` も、文書の単位で渡します。
- **文書がない場合:** Rhino の文書がない場合（Rhino の外で動かした場合など）は、メートルのまま出します。

### 地域設定

- **数値の読み方:** GMLの数値は、PC の地域設定（小数点が「,」の言語など）に関係なく、「.」を小数点として読みます。
- **以前の不具合:** 以前は、ドイツ語の設定では座標が警告なしに狂い、フランス語の設定ではエラーになりました。

## 使用例

### 基本的な使用方法

```
1. dem2mesh.gh を開く
2. File Path で GML ファイルを選ぶ（複数可）
3. 平面直角座標系の系を選ぶ（分からなければ自動判定）
4. output_mesh から生成されたメッシュを取得（必要なら Bake）
```

### 複数区画の読み込み

```
1. 隣り合う区画のGMLを、1ファイル1要素のリストにして xml_data に接続
   （xml_data の入力は List Access。ツリーで渡す場合は Flatten してから）
2. 全区画が1つの格子にまとめられ、1枚のメッシュとして出力される
```

- 区画の順番は問いません。欠けている区画があっても、その部分に面ができないだけです。
- 1m・5m・10mなど、**セルの大きさが違うデータは混ぜられません**（エラーになります）。
- ゾーンは全区画の中心から1つだけ決めます（自動検出の場合）。
- クリッピングを指定すると、範囲にかからない区画は標高を読まずに飛ばします。
- 統合した格子が5,000万セルを超える場合はエラーになります。離れた区画を同時に読み込んでいないか確認してください。
- 同じ5mでも、DEM5A/5B/5C のように精度や計測時期の違う区画を並べると、境目に段差が出ることがあります（国土地理院の注意事項）。
- 2025年7月31日より前にダウンロードした区画（測地成果2011の標高）と新しい区画を混ぜた場合も、境目に段差が出ます（「注意: 測地成果2011と測地成果2024」を参照）。

### 種別による色分け（type_output）

GMLの標高データには、`地表面,33.74` のように点ごとに種別が付いています。
仕様書（V5.3「DEM構成点種別」）の種別は、地表面・表層面・海水面・内水面・海水底面・内水底面・データなし・その他です。
`type_output` を 1 か 2 にすると、この種別でメッシュを分けて色を付けます。

| type_output | output_mesh | type_meshes / type_names |
|---|---|---|
| 0 | 1枚のメッシュ（色なし。従来どおり） | 空 |
| 1 | 空 | 種別ごとのメッシュ（色付き）と種別名 |
| 2 | 種別ごとのメッシュを結合した1枚（色付き） | 種別ごとのメッシュ（色付き）と種別名 |

- **面の種別:** 面の4隅で一番多い種別にします。同数のときは、地表面以外（水部など）を優先します（優先順: 海水面 → 内水面 → 海水底面 → 内水底面 → 表層面 → その他 → データなし → 地表面）。1セル幅の細い川や水路でも消えないようにするためです。
- **すき間はできません:** 各面はどれか1つの種別に必ず入ります。境目の頂点は、両側のメッシュに同じ座標・同じ標高で複製されます。種別ごとのメッシュの面を合わせると、`type_output` = 0 のメッシュの面と完全に一致します。
- **結合（2）の扱い:**
  - 境目の頂点は溶接しません。溶接すると、境目の面の色が隣の種別と混ざるためです。
  - 頂点は境目で2つずつ持ちますが、同じ座標にあるので、Rhino はつながった1枚として扱います。Rhino 8 で確かめたところ、開いた辺（naked edge）は外周だけで、`type_output` = 0 のメッシュと同じでした。つながった塊の数（DisjointMeshCount）も 1 です。
  - Shaded 表示では、種別の境目に濃い線が見えることがあります。
- **境目の位置:** 種別の境目は、セルの境界ではなく面の境界（セルの中心を結んだ線）に沿って引かれます。本来の境目から最大で半セルずれます。
- **色:** 種別ごとに決まった色を付けます。

  | 種別 | 色（RGB） |
  |---|---|
  | 地表面 | 196,170,130 |
  | 表層面 | 110,160,90 |
  | 海水面 | 40,90,170 |
  | 内水面 | 90,170,220 |
  | 海水底面 | 30,60,120 |
  | 内水底面 | 60,130,160 |
  | その他・表にない種別 | 160,160,160 |

- **面ができない部分:** 海水面とデータなしは標高が `-9999` なので、色分けしても面はできません（もともと穴になります）。また、令和5年度の仕様変更より前に作られた DEM5A では、内水面も `-9999` です（国土地理院 FAQ Q.4-17）。
- **内水面の標高:** 内水面の標高は参考値で、精度評価の対象外です（同 FAQ）。
- **種別名の扱い:** 仕様書の表にない種別名が出てきた場合は、そのままの名前で別のメッシュにし、灰色にします。
- **間引きとの関係:** `sample_step` で間引いた場合は、残った点の種別で決めます。

### ゾーン指定

```
東京付近: jgd_zone = 9
大阪付近: jgd_zone = 6
自動検出: jgd_zone = 0（またはマイナス値）
```

### 範囲クリッピング

```
target_point: クリッピングしたい中心の座標（平面直角座標系、Rhino の文書の単位）
size: クリッピング範囲の一辺（文書の単位。m の文書なら 1000 で 1km四方、mm の文書なら 1000000）
```

## 技術仕様

### 座標系
- **入力**: 世界測地系（JGD2011 / JGD2024）緯度経度
- **出力**: 平面直角座標系の座標。Rhino の X が東（平面直角座標系の Y）、Rhino の Y が北（同 X）。単位は Rhino の文書の単位
- **楕円体**: GRS80
  - 長半径 a = 6,378,137 m
  - 扁平率 f = 1/298.257222101

### 注意: 測地成果2011（JGD2011）と測地成果2024（JGD2024）

2025年4月1日に、国土地理院の測量成果が「測地成果2011」から「測地成果2024」に改定されました。
あわせて、測地系の名称が JGD2011 から JGD2024 に変わりました。

**緯度経度・平面直角座標は変わっていません**
- 改定されたのは標高だけです。測地系の名称は変わりましたが、定義は同じです。
- 2025年4月以降に提供されたGMLは `srsName="fguuid:jgd2024.bl"` となっていますが、このスクリプトはどちらの表記も区別せず、同じ計算で平面直角座標に変換します。
- 出力の X, Y はJGD2011とJGD2024のどちらで扱っても同じ値です。

**標高は改定されています**
- 基盤地図情報の数値標高モデルは、2025年7月31日から改定後の標高で提供されています。
- 改定の対象は **DEM1A・5A・5B・5C** です。DEM10A・10B は改定されていません。
- 改定量は地域によって異なります。水準点では最大で +23cm（宮城県牡鹿半島）から -40cm（北海道別海町）で、一部の離島ではこれを超えます。

**混ぜて使うときの注意**
- **古い区画と新しい区画を同時に読み込まない。** それより前にダウンロードした区画（2011の標高）と新しい区画を一緒に読み込むと、境目で標高が数cmから数十cm食い違うことがあります。このスクリプトはどちらの標高かを判別せず、そのまま1つのメッシュにまとめます。エラーや警告は出ません。
- **ダウンロード日で見分ける。** ファイル中の `srsName` やファイル名の日付だけで、標高が改定後かどうかを見分けられるかは確認できていません。データはダウンロード日で管理し、迷ったら同じ時期にまとめてダウンロードし直してください。
- **srsName が混ざっていたら警告が出る。** info の `== Tiles ==` に、区画ごとのメッシュ番号と `srsName`（旧: `fguuid:jgd2011.bl`、新: `fguuid:jgd2024.bl`）を表示します。メッシュに使った区画の `srsName` が混ざっているときは、info の先頭に `Warning:` を出します。メッシュはそのまま作られます。クリッピングで外れた区画（`(skipped)`）は警告の対象外です。表記が揃っていても標高が揃っているとは限らないことは、上の注意のとおりです。
- **補正して揃える。** 古いDEMを新しい標高に合わせる（または逆に戻す）には、国土地理院の「基盤地図情報等パラメータ補正ツール」を使います。数値標高の補正には、水準点標高補正パラメータ（`hyokorevBM_jgd2024_h.par`）を使います。
- **他の資料と重ねるときも基準を確かめる。** 測量図面・点群・BIMなど、ほかの資料と重ねる場合は、相手の標高が測地成果2011と2024のどちらに基づくかを確認してください。平面位置は合っていても、高さだけが数十cmずれることがあります。

参考: [全国の標高成果の改定に関するQ&A](https://www.gsi.go.jp/sokuchikijun/hyoko2024rev-QA.html)（Q1-6, Q1-9, Q1-3, Q3-2, Q3-5）、[基盤地図情報ダウンロードサービス ヘルプ](https://service.gsi.go.jp/kiban/app/help/)、基盤地図情報ダウンロードデータファイル仕様書 V5.3「3.1 座標参照系」

### 座標変換アルゴリズム
国土地理院「測量計算サイト」の計算方法に準拠したガウス・クリューゲル図法（6次展開）による変換です。

- **係数:** α1～α6 の係数を使い、原点の子午線弧長 S0 を A0～A6 で計算します。これらは楕円体と原点だけで決まるので、最初に1回だけ計算します。
- **計算の工夫:** sin・cos（2jξ）と sinh・cosh（2jη）は加法定理の漸化式で求め、点ごとの三角関数・双曲線関数の呼び出しを減らしています。
- **精度:** 国土地理院の測量計算サイト（緯度経度 → 平面直角座標）の結果と、系の中央から離れた点を含む5点で 0.05 mm 以内で一致しました（3・9・12・13・16系。テストに含めています）。

- **並列処理**: Parallel.Forによる高速化
- **メモリ効率**: 無効点の削除と頂点の最適化

### 扱える区画数の目安（実測）

測定環境：Rhino 8.35、メモリ 32GB、16コア。サンプル（2次メッシュ 513253、DEM5A）の区画を正方形にまとめて、間引きなし（`sample_step` = 1）で測りました。DEM5A は1区画 225×150点（約3.4万点）です。

| 区画数 | 点の数 | 面の数 | 作成時間 type_output=0 | 作成時間 type_output=2 |
|---|---|---|---|---|
| 1 | 3.4万 | 3.3万 | 0.02 秒 | 0.05 秒 |
| 4 | 13.5万 | 13.4万 | 0.11 秒 | 0.19 秒 |
| 9 | 30万 | 30万 | 0.26 秒 | 0.32 秒 |
| 25 | 84万 | 84万 | 0.70 秒 | 0.96 秒 |
| 49 | 165万 | 165万 | 1.4 秒 | 1.8 秒 |
| 100（2次メッシュ全体） | 338万 | 337万 | 2.7 秒 | 3.7 秒 |

- **測り方:** 作成時間は Version 1.2 で、2回測った短いほうです。Version 1.1（6次展開で、定数を点ごとに計算）では、100区画で 3.0 秒・3.7 秒でした。
- **時間:** 区画の数にほぼ比例し、1区画あたり 30〜40 ミリ秒です（ファイルの読み込みは別に 1区画あたり約 2.5 ミリ秒）。
- **Grasshopper:** 100区画を Grasshopper のコンポーネントで読み込むと、計算に約5秒かかりました。Bake は約0.4秒でした（どちらも Version 1.1 で測定）。
- **メモリ:** 100区画では、Rhino の使用メモリが 0.7〜0.9 GB 増えました。
- **表示:** Rhino の文書に入れたメッシュ（100区画、色付き）は、最初の表示に約4秒かかります。そのあとは、回転しても1回の描画が 10 ミリ秒以下でした。
- **保存:** 100区画の色付きメッシュを .3dm に保存すると、約26秒・161 MB でした。
- **Grasshopper のプレビュー（測れなかった）:** 100区画のメッシュを出したまま Grasshopper のウィンドウを開いていると、Rhino の応答が何度か長く止まりました。プレビューの描画時間そのものは測れていません。

**目安**
- **100区画（2次メッシュ1つ分、約11×9 km）まで:** 間引きなしでも動きます。数十区画を超えるときは、Grasshopper のプレビューを切って（コンポーネントを右クリック → Preview をオフ）、必要なときに Bake するのが安全です。
- **それより広い範囲:** `sample_step` を 2 以上にすると、点の数は 1/4 以下になります。実際に試したのは100区画までです。
- **上限:** スクリプトの上限は、まとめた格子が5,000万セル（DEM5A で約1,480区画）までです。ただし、100区画で 0.8 GB 前後増えたことから考えると、1,000区画規模を間引きなしで扱うと、メッシュだけで数GB以上になると見込まれます（推定）。

## エラー処理

### 主なエラーメッセージ

- `"Wait: xml_data が未入力です。"`: XMLデータが提供されていません
- `"Error: [詳細]"`: 解析エラーまたは変換エラー。区画ごとの問題は `区画 n:` のように入力リストでの番号（1から）を示します
- `"Error: 区画 n のセルの大きさが区画 1 と違います"`: 解像度の違うデータが混ざっています
- `"Error: 区画 n の格子が区画 1 の格子と揃っていません"`: 区画の位置がセルの整数倍でずれていません
- `"Error: 区画をまとめた範囲が広すぎます"`: 区画どうしが離れすぎています
- `"クリッピング範囲にかかる区画がありません。"`: target_point と size の範囲に区画がありません
- `"Warning: srsName の違う区画が混ざっています（…）"`: JGD2011 と JGD2024 など、座標参照系の表記が違う区画を同時に使っています。メッシュは作られますが、境目に標高の段差が出ることがあります

### トラブルシューティング

1. **メッシュが生成されない**
   - XMLデータの形式を確認
   - sample_stepを小さくしてみる
   
2. **座標がおかしい**
   - jgd_zoneを手動で指定
   - 対象地域に適切なゾーンか確認
   - 大きさが1000倍・1000分の1に見える場合は、info の `Units:` で Rhino の文書の単位を確認

3. **処理が遅い**
   - sample_stepを大きくする
   - 数十区画を超えるときは、Grasshopper のプレビューを切って Bake する

## テスト

`dem2mesh.cs` を変えたときに確かめるテストが `tests/` にあります。Rhino がなくても、Windows に入っている .NET Framework の C# コンパイラで動きます。

**実行方法**（このフォルダで）:

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_tests.ps1
```

`sample` 以外の場所にあるGMLで試すときは、フォルダを指定します。

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_tests.ps1 -SampleDir C:\path\to\FG-GML-513253-DEM5A-20250620
```

- **結果の見方:** 1件ごとに `PASS` / `FAIL` / `SKIP` が出て、最後に件数が出ます。
- **終了コード:** 0 = すべて成功、1 = 失敗あり、2 = ビルドできない。
- **合成データのテスト（常に実行、65件）:**
  - 座標変換と国土地理院の計算値（5点）
  - 標高点の位置（セルの中心）
  - 複数区画の統合
  - 先頭・末尾の省略
  - クリッピング
  - 入力の誤り
  - 1〜19系の原点
  - 地域設定（ドイツ語・フランス語・ロシア語でも同じ結果）
  - Rhino の文書の単位（m・mm、切り抜き）
  - 種別による分け方
  - srsName の警告
- **実データのテスト（テスト用のデータがあるときだけ、12件）:** 区画の境目のつながり、種別による分け方、srsName、全区画の読み込みを確かめます。
  - **使うデータ:** 2次メッシュ **513253**（広島市付近）の **5mメッシュ（DEM5A）** を使います。中の区画（06・07・16・17・52・53・62・63 など）を名前で探すため、この2次メッシュでないと実行できません。
  - **置き場所:** ダウンロードしたフォルダを、展開したまま `sample/` の下に置きます（例: `sample/FG-GML-513253-DEM5A-20250620/`）。
  - **データが無いとき:** `SKIP` になり、失敗にはなりません。
- **テストで見られない範囲:** テストは仮の Rhino の型で動くので、Rhino での表示、Grasshopper のプレビュー・Bake、入出力の設定は確かめられません。開発時の決まりは `CLAUDE.md` にまとめてあります。

### 使用データについて

MITライセンスは、このスクリプト（`dem2mesh.cs`、`dem2mesh.gh`）だけに適用されます。読み込む基盤地図情報には適用されません。

国土地理院が作成した基盤地図情報は **基本測量成果** で、使い方によっては測量法に基づく承認が必要です（基盤地図情報 FAQ Q.1-7）。国土地理院の資料から読み取れる範囲を、使い方ごとにまとめます。

| 使い方 | 手続き | 根拠 |
|---|---|---|
| 個人・組織の中で使う（設計の検討など） | 申請不要。出典を明示する | 測量成果の利用手続（内部利用は申請不要） |
| ダウンロードしたGMLを、そのまま（または形式を変えて）第三者に配る・インターネットで公開する（リポジトリへの同梱を含む） | **複製承認**（測量法第29条） | 事例集「GISシステムのサンプルデータとしてベクトルデータを同梱して配布」 |
| このスクリプトで作ったメッシュ・3Dモデル・画像・立体模型を公開・配布する | **使用承認**（測量法第30条） | 事例集「標高データから鳥瞰図を作成（3Dモデル画像、3Dプリンタによる立体地形模型など）」 |

- **承認の申請:** 承認は「測量成果ワンストップサービス」（オンライン）か郵送で申請します。標準の処理期間は、申請書の到着から7〜14日程度です。基盤地図情報の複製は、営利・非営利を問わず無償で承認されます（承認申請Q&A Q5-4）。
- **出典の書き方:** 申請不要の場合でも出典は必要です。加工したときは、加工したことも書きます。
  - 例: 「出典：国土地理院 基盤地図情報（数値標高モデル）」
  - 例: 「国土地理院 基盤地図情報（数値標高モデル）を加工して作成」
  - 国土地理院が作ったように見える形で公表してはいけません（同 Q1-15）。
- **インターネットで公開することになる場合:** 誰でも見られるサイトやブログは「インターネット等により情報を提供する場合」に当たります。参加者が互いに特定できる範囲のサイトは当たりません（同 Q2-3）。このリポジトリを公開リポジトリにする場合も、GMLを含めないでください。
- **国土地理院以外が整備したデータ:** 一部の区画は、国土地理院以外の機関が整備しています。整備者は、データのメタデータで確認できます（FAQ Q.1-3, Q.1-6）。
- **判断に迷う場合:** 上の表は資料の読み取りで、法的な判断ではありません。具体的な使い方が承認の対象になるかは、国土地理院の「地図の利用手続ナビ」で確認するか、国土地理院に問い合わせてください。
